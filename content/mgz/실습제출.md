# 실습제출

![[attachments/image 30.png]]

각 컴포넌트를 클릭하면 더 자세한 설명을 볼 수 있어요. 흐름을 요약하면:

1. **Consumer VPC** — EC2가 `vpce-xxx` DNS 주소로 curl 요청
2. **VPC Endpoint (ENI)** — Private IP로 요청을 받아 AWS 내부망으로 전달
3. **AWS 내부망** — 인터넷을 거치지 않고 Provider VPC로 라우팅
4. **Endpoint Service → NLB → EC2 B** — 순서대로 트래픽 전달 후 응답 반환

### 클로드

**AWS PrivateLink**를 통해 VPC Endpoint로 백엔드 API를 호출한 것입니다.

## 구성 요소 분석

**URL 구조:**

`http://vpce-0101d1f59eb456a0a-hx120s57.vpce-svc-0dd74ecc3aa439192.ap-northeast-2.vpce.amazonaws.com`

- `vpce-xxx` → VPC Endpoint ID
- `vpce-svc-xxx` → VPC Endpoint Service ID
- `ap-northeast-2` → 서울 리전

**응답 결과:**

json

`{"message":"Hello from Backend API","server":"EC2 B","service":"privatelink-demo"}
```

---

## 이 결과를 얻기 위한 전체 구성 과정

### 1️⃣ 서비스 제공자 측 (Provider VPC)
```
EC2 (백엔드 API 서버)
    ↓
NLB (Network Load Balancer) 생성
    ↓
VPC Endpoint Service 생성 (NLB 연결)`

bash

`# NLB Target Group에 EC2 등록 후
# Endpoint Service 생성
aws ec2 create-vpc-endpoint-service-configuration \
  --network-load-balancer-arns <NLB_ARN> \
  --acceptance-required false
```

### 2️⃣ 서비스 소비자 측 (Consumer VPC)
```
VPC Endpoint 생성 (Interface type)
    ↓
Endpoint Service에 연결
    ↓
DNS 이름 자동 생성됨`

bash

`aws ec2 create-vpc-endpoint \
  --vpc-id <VPC_ID> \
  --service-name com.amazonaws.vpce.ap-northeast-2.vpce-svc-xxx \
  --vpc-endpoint-type Interface \
  --subnet-ids <SUBNET_ID> \
  --security-group-ids <SG_ID>`

### 3️⃣ EC2에서 curl 호출

bash

`# Consumer VPC의 EC2에서
curl http://vpce-xxxx.vpce-svc-xxxx.ap-northeast-2.vpce.amazonaws.com`

## 핵심 포인트

| 항목 | 설명 |
| --- | --- |
| **통신 방식** | 인터넷을 거치지 않고 AWS 내부망으로 통신 |
| **보안** | Public IP 불필요, Private 통신 |
| **EC2 B** | NLB 뒤에 있는 백엔드 서버 |

## 젬미니

이미지에서 보이는 결과는 **AWS PrivateLink**를 사용하여 서로 다른 VPC에 있는 서비스 간에 **프라이빗 통신**을 성공적으로 수행한 모습입니다.

이 결과를 얻기 위해 구성해야 하는 핵심 단계들을 정리해 드릴게요.

---

## 1. 주요 구성 요소

이 시나리오는 보통 두 개의 VPC(서비스 제공자 VPC와 서비스 소비자 VPC) 사이에서 이루어집니다.

- **서비스 제공자 (Backend):**
    - **EC2 인스턴스 (EC2 B):** "Hello from Backend API"라는 응답을 보내는 웹 서버가 구동 중입니다.
    - **Network Load Balancer (NLB):** Backend EC2를 타겟으로 연결합니다. (PrivateLink는 반드시 NLB가 필요합니다.)
    - **VPC Endpoint Service:** NLB를 기반으로 생성하며, 다른 VPC에서 접속할 수 있는 '서비스 통로'가 됩니다.
- **서비스 소비자 (Client):**
    - **EC2 인스턴스 (EC2 A):** 이미지에서 `curl` 명령어를 입력하고 있는 주체입니다.
    - **Interface VPC Endpoint:** 제공자의 'Endpoint Service'와 연결되어 생성되는 프라이빗 네트워크 인터페이스입니다. 이미지의 긴 도메인(`vpce-0101d...`)이 바로 이 엔드포인트의 DNS 이름입니다.

---

## 2. 전체 흐름 (Step-by-Step)

## **단계 1: 백엔드 서버 준비**

1. **EC2 B**에 간단한 API 서버(Node.js, Python, Nginx 등)를 띄워 JSON 응답이 나오도록 설정합니다.
2. 이 EC2를 **Network Load Balancer (NLB)**의 타겟 그룹에 등록합니다.

## **단계 2: Endpoint Service 생성 (제공자 쪽)**

1. AWS 콘솔의 VPC 메뉴에서 **Endpoint Services**로 이동합니다.
2. 방금 만든 NLB를 선택하여 서비스를 생성합니다.
3. 이때 생성된 **Service Name**(`com.amazonaws.vpce.ap-northeast-2.vpce-svc-...`)을 복사해둡니다.

## **단계 3: Interface Endpoint 생성 (소비자 쪽)**

1. 소비자 VPC 내의 **Endpoints** 메뉴로 이동합니다.
2. **Create Endpoint**를 누르고 "Other endpoint services"를 선택한 뒤, 단계 2에서 복사한 서비스 이름을 입력합니다.
3. 생성이 완료되면 이미지에 보이는 것과 같은 **DNS names**가 발급됩니다.

## **단계 4: 테스트**

1. 소비자 쪽의 **EC2 A**에 접속합니다.
2. 발급받은 DNS 이름을 대상으로 `curl` 명령어를 실행합니다.Bash
    
    `curl http://vpce-0101d1f59eb456a0a-hx120s57.vpce-svc-0dd74ecc3aa439192.ap-northeast-2.vpce.amazonaws.com`
    

---

## **주의사항**

- **보안 그룹(Security Group):** 백엔드 EC2와 NLB, 그리고 소비자 쪽의 VPC Endpoint 인터페이스에 각각 적절한 포트(보통 80) 허용 규칙이 있어야 합니다.
- **비용:** PrivateLink는 데이터 처리량 및 시간당 비용이 발생하므로 실습 후에는 엔드포인트를 삭제하는 것이 좋습니다.

직접 실습을 해보고 싶으신가요? 특정 단계(예: NLB 설정 방법 등)에 대해 더 자세한 설명이 필요하시면 말씀해 주세요!

이 다이어그램은 `ap-northeast-2` (서울) 리전 내에 구성된 두 개의 가상 프라이빗 클라우드(VPC)를 보여줍니다.

1. **Consumer VPC (소비자 VPC):**
    - 이 VPC는 외부 서비스를 소비하는 클라이언트 측입니다.
    - **클라이언트 EC2 (EC2 A):** `curl` 명령어를 실행하는 주체입니다. 이 EC2는 프라이빗 서브넷에 위치하며 직접적인 인터넷 접속이 없습니다.
    - **Interface VPC Endpoint:** 이 서비스의 핵심 구성 요소입니다. 소비자 VPC의 가용 영역(AZ)에 프라이빗 IP를 가진 ENI(Elastic Network Interface)로 생성됩니다. 이미지의 긴 도메인(`vpce-01d789...`)은 이 엔드포인트의 DNS 이름으로, `curl` 트래픽을 이 프라이빗 IP로 유도합니다.
2. **AWS Network Backbone:**
    - Consumer VPC의 Interface Endpoint와 Provider VPC의 Endpoint Service 사이의 통신은 인터넷 게이트웨이(IGW), NAT 게이트웨이, 또는 VPC 피어링을 거치지 않습니다.
    - 트래픽은 AWS 전용 광섬유 네트워크인 **AWS Network Backbone**을 통해 직접 전달되어, 가장 높은 수준의 보안과 낮은 지연 시간을 보장합니다.
3. **Provider VPC (제공자 VPC):**
    - 이 VPC는 비공개로 노출할 서비스를 호스팅하는 측입니다.
    - **Network Load Balancer (NLB):** PrivateLink 서비스를 생성하기 위한 **필수** 전제 조건입니다. NLB는 프라이빗 IP를 가지고 소비자로부터 온 트래픽을 받아 등록된 타겟으로 부하 분산합니다.
    - **웹 서버 EC2 (EC2 B - 원본 백엔드):** NLB의 타겟 그룹에 속해 있습니다. `curl` 요청에 대해 `"Hello from Backend API", "server":"EC2 B"`라는 JSON 응답을 보내는 실제 API 서버가 구동 중입니다.
    - **VPC Endpoint Service:** 이 구성 요소는 제공자 VPC 내의 NLB를 기반으로 소비자 VPC에 안전한 서비스를 노출하는 '게이트웨이' 역할을 합니다.

이 구조를 통해 이미지에서 보시는 것과 같이 프라이빗 서브넷의 EC2 A에서, 또 다른 프라이빗 네트워크에 있는 EC2 B의 API를 안전하고 비공개적으로 호출할 수 있습니다.
